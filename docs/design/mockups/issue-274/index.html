Do not reserve shell chrome during session validation

A sidebar or header skeleton would resemble an authenticated workspace before the session and role are known. That conflicts with the settled criterion that no otherwise usable workspace may appear without its enabled sign-out control.

This is a full-viewport state replacement, not a partially painted workspace inside persistent chrome. The resolved shell has a different geometry, but that change occurs at an authentication boundary. It is not cumulative layout shift caused by late content inside a stable screen, and preserving the boundary is more important than visually approximating the next state.

Minimal refinement: keep the current logo, spinner, and role-specific copy; expose the copy through a polite live region; and avoid flashing the loading view when the session response returns immediately. No new visual token is needed.

Advisory acceptance notes

Deep-entry behavior remains route-consistent

Query strings and fragments

?query=value and #fragment do not change shell selection or sign-out placement. Visual behavior is identical.

Cross-role entry

Resolve the session before shell paint, then redirect to the correct workspace or sign-in. Never flash the other role's shell.

After sign-out

Administrator exits land on /sign-in. Staff exits land on /staff/sign-in. Keep the polite role="status" line “You have been signed out.”

Refresh after sign-out

Refreshing the original protected deep address must not restore the workspace. Session validation must resolve to the role-correct sign-in screen.

Loading accessibility

Announce validation politely. Ensure the loading tree can unmount without dropping focus into an inert or removed element.

Control accessibility

Keep the 44px minimum target, visible focus ring, stable in-flight footprint, disabled state, and aria-busy="true".
