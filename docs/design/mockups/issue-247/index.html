Count the drinks handed over, without changing the sale

A preserve-mode specification for adding Product.packagingServings to the existing product editor and reconciliation flow.

Binding: this integer affects cup and lid counting only. It never changes price, discount, tax, or the order total.
1

The servings field in the product editor

Add one plain number input after the existing details grid and before the existing state settings.

Decision

Use a native number input, not a stepper or disclosure. Default it to 1. The common case is already resolved, while the visible field keeps a consequential value auditable. A value above 1 gains an existing badge that states the counted drinks per sale.

Products list: show the exception at a glance

Keep the five columns. Put one promotion-colored badge beside Product name only when the value is greater than 1.

Decision

Show the non-default value in the Product name cell. A separate column would spend permanent width on a rare exception. The badge makes an accidental 2 visible during routine catalog scans and disappears entirely for the default value of 1.

Close-of-day cup and lid balance

No visual change. The story changes only the arithmetic that supplies Expected.

Decision

Add no cashier-facing annotation. Expected already represents packaging usage, not order-line count. Explaining promotion arithmetic here would add end-of-shift reading cost and reopen a regression-prone layout for information the cashier cannot act on.

Accessibility and token notes

Use the existing field semantics and tokens. No new token is needed.

implementation checks

Label and description

The visible <label> targets the input. In the valid state, aria-describedby points to help. In the invalid state, it points only to the rendered error.

Validation state

Set aria-invalid="true" only after validation fails. Accept integers of 1 or greater. Use the same error for blank, zero, negative, and fractional values.

Native number behavior

type="number" supplies keyboard increment and decrement through Arrow Up and Arrow Down. Browser spinner styling varies, the wheel may alter a focused value, and decimal separators follow locale conventions. Server validation remains authoritative.

Touch and keyboard

The input keeps the production 44px minimum height. No custom buttons are added, so there are no extra tab stops or touch targets. Tab, Shift+Tab, Arrow Up, Arrow Down, and direct entry cover operation.

Badge contrast

The exception marker uses --promotion-ink on --promotion-surface with --promotion-border. Text carries the meaning; the 7px dot is decorative and hidden from assistive technology.

Tokens

New tokens: none. The input uses existing field tokens and the rare non-default marker uses the existing promotion token family.

Implementation note: prevent accidental wheel changes if production has observed them, but do not globally blur number inputs. Prefer saving only after explicit form submission and validate the integer again at the API boundary.
