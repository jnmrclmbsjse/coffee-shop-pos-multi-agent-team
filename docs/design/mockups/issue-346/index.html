Compensation adjustments

Advisory implementation reference for Story #346. This extends the shipped admin Compensation area; it does not define a second product.

Developer reference Static HTML, CSS, and vanilla JS Admin-only surface
A. Placement B. Adjustments list C. Add / edit D. Delete E. Payslip F. PNG download

A. Placement

Extend Compensation in place

Decision

Add Adjustments as the third segment in the shipped Compensation switch. Standalone dated money rows have different fields, validation, and lifecycle from daily work records. Folding them into Daily records would blur that model and make earnings and deductions harder to scan.

B. Adjustments list

Make kind and direction unmistakable

Decision

First load shows all adjustments for the current calendar month, newest effective date first. A badge, signed amount, and left-edge marker carry kind together, so meaning survives low colour perception and quick scanning. Identical rows are valid and remain unremarked.

C. Add / edit an adjustment

One honest form for all three kinds

Decision

Description is always a required, editable text field. Presets only fill that field and never create a stored code. There is deliberately no duplicate warning state: the model permits identical adjustments on the same date.

D. Delete confirmation

Name the exact row before hard delete

Decision

The confirmation repeats staff member, date, kind, description, and amount. Delete is permanent and has no undo, so the dialog states that plainly before the destructive action.

E. Payslip with adjustments

Earnings above the rule, advances below

Decision

Every allowance and bonus remains itemized in earnings; advances are the only deduction. Net payable is the dominant total and may be negative. Keep grandTotalCents in the API only: showing it beside earnings total would introduce a confusing near-duplicate subtotal.

F. PNG download

Capture the visible artifact node

Decision

Place Download PNG in the artifact header after a successful non-empty generation. Export the same node the admin sees, preserving the itemization, range, totals, and generated timestamp.

Rasterization safety

DOM-to-image output can differ when web fonts are still loading, when a renderer cannot resolve oklch(), or when shadows and gradients are approximated. Scroll containers can clip content; sticky or positioned elements and off-screen overflow can move or disappear.

Recommendation: capture a self-contained node with no horizontal scroll region, use fully loaded system fonts, and flatten unsupported paint effects in an export-only style if testing shows a mismatch.
