# UCM Coffee Studio Admin Order History

## Register

product

## Users

The primary user is the owner or manager of a single-location coffee shop. They use the Admin interface in a bright back-office environment, often while answering a customer question or reconciling a trading day. They need to locate a historical order quickly, understand its payment and settlement state, and verify line-item discounts without changing the record.

## Product Purpose

Order History provides a read-only record of sales orders across business days. It helps the owner find an order by its paired business-day and order-number identity, distinguish completed, parked, and void history, and inspect financial details such as split payments, tips, discounts, and change settlement.

Success means the owner can answer common order questions accurately from one compact workflow, without confusing history review with production order actions.

## Brand Personality

Calm, operational, and precise. The interface should feel familiar to frequent Admin users, readable in bright ambient light, and quiet enough that order values and exceptional states carry the hierarchy.

## Anti-references

- Marketing-page styling, oversized typography, decorative imagery, gradients, or glass effects.
- Consumer point-of-sale capture patterns that suggest creating or editing an order.
- Alarm-heavy status styling that treats Void as an error or Parked as a warning.
- Sparse card layouts that hide comparable data or require excessive scanning.

## Design Principles

1. Keep history read-only and visually distinct from order capture.
2. Make the business day and order number work as one identity.
3. Preserve financial truth, including original positive values on void orders and explicit unavailable values.
4. Use compact density without reducing target size, focus visibility, or text clarity.
5. Let words carry status and settlement meaning; color may support but never replace them.

## Accessibility & Inclusion

The mockup targets WCAG 2.2 AA. It uses semantic landmarks and tables, a skip link, visible keyboard focus, minimum 44px targets, explicit labels, text-based state distinctions, live result announcements, reduced-motion support, and responsive navigation. Unavailable values use the story-required glyph “—”.
